# 后端实现

FastAPI 后端位于 `backend/`，采用 MVC 分层：`controllers/`（路由与请求处理）、`models/`（SQLAlchemy 表）、`services/`（可复用业务逻辑）、`schemas.py`（Pydantic 校验）、`database.py`（引擎与热切换）、`auth.py`（认证依赖）。

## 启动流程

入口 `app/main.py`。在**模块导入时**（创建 `FastAPI()` 之前）依次执行：

1. `setup_database()` → `recreate_schema(get_engine())`
2. `_seed_admin()`：若 `admins` 表为空，插入 `admin` / `admin123`（角色 `super`）

随后创建应用、挂 CORS（`allow_origins=["*"]`）、注册路由、暴露 `GET /api/health`。

### `recreate_schema(engine)`

幂等初始化/升级，串联三步：

- `Base.metadata.create_all()` 建表；
- `_ensure_columns(engine)` 补列（无 Alembic 的轻量迁移）；
- `_ensure_oracle_identity(engine)` 修复 Oracle 主键自增。

### `_ensure_columns(engine)`

用 SQLAlchemy `inspect(engine)` 列出表与列，缺列时执行 `ALTER TABLE ... ADD COLUMN`（`_add_column` 对 MSSQL/Oracle 用 `ADD`，其余用 `ADD COLUMN`）。覆盖的表与补列包括：

- `settings`：logo/favicon/site_title/theme/debug、admin_secret、assistant、SMS 与验证码配置、搜索配置、限额、各渠道系统提示词、钉钉/飞书凭据等
- `users`：assistant 字段、dingtalk/feishu userid、协议、department_id、token_limit_daily
- `admins`：role、department_id
- `departments`：token_limit_daily
- `messages`：tokens、endpoint_id
- `conversations`：bot_id、mcp_ids、skill_ids
- `knowledge_bases`、`api_endpoints`、`mcp_servers`、`skills`、`wecom_bots`：scope/system_prompt 等

### `_ensure_oracle_identity(engine)`

仅 Oracle 生效。对每个用 `Identity()` 声明的主键列，若当前仍非 identity，则 `MODIFY (... GENERATED BY DEFAULT AS IDENTITY)` 并 `RESTART START WITH max(id)+1`，解决旧 schema 下显式插入主键返回 NULL（ORA-01400）的问题。

## 配置 `config.py`

`pydantic_settings.BaseSettings`，从 `backend/.env` 读取（`env_prefix=""`），导出单例 `config`。字段见 [部署文档](deployment.md#环境变量)。

## 数据库层 `database.py`

- `Base` 为声明基类，被所有模型共享。
- 数据库 URL 解析优先级：`data/db_config.json`（后台热切换写入） > 环境变量 `DATABASE_URL` > 默认 `sqlite:///./data/app.db`。
- `get_engine()` / `get_sessionlocal()` 访问当前引擎与会话工厂；`get_db()` 是 FastAPI 依赖。
- `reconfigure(cfg)` 热切换引擎并释放旧引擎；`save_config(cfg)` 持久化配置；`current_db_info()` 返回脱敏信息。

## 认证与权限 `auth.py` / `security.py`

- `create_token(user_id)`：用户 JWT（7 天有效）。
- `create_admin_token(username, role, department_id)`：管理员 JWT。
- 依赖项：`get_current_user`、`get_current_admin`（要求 `role ∈ {super, dept}`）、`require_super`（否则 403）、`require_dept`（要求部门管理员且已绑定部门）。
- 密码：`security.py` 使用 PBKDF2-HMAC-SHA256、20 万次迭代、16 字节随机盐，存储格式 `"{salt}${digest}"`。
- 角色：`super`（超级管理员，全部权限）、`dept`（部门管理员，仅本部门成员与用量）。普通用户无角色字段。

## 数据库热切换

配置持久化在 `data/db_config.json`，结构 `{type, path, host, port, database, username, password}`。

`services/db.py` 支持 `sqlite` / `mysql`（pymysql）/ `postgresql`（psycopg2）/ `mssql`（pymssql）/ `oracle`（oracledb）。Oracle 使用 `?service_name=<database>` 连接（避免 ORA-12505）。

`POST /api/admin/db/switch` 流程：

1. 校验配置 → 2. `test_connection` → 3. `db_migrate.migrate(..., backup=True)` → 4. `save_config` → 5. `reconfigure`（热切换引擎）→ 6. `recreate_schema` → 7. 写审计日志。

迁移 `db_migrate.migrate`：建目标表 → 非覆盖模式下若目标已有数据则中止 → 按外键依赖排序逐表复制（保留主键）→ MSSQL `IDENTITY_INSERT` / Oracle·PG 序列复位 → 提交。附件文件不迁移。
